# Data contract and governance
Purpose: help novice readers find a candidate visualization component and inspect an analogous public specification. Prospective community: DKU students in Kunshan learning visualization across disciplines; need remains hypothetical.
Action / target: retrieve a component for an English-language task, inspect an input/output relationship, and distinguish a source annotation from an external implementation example. Supported claim: deterministic retrieval and source-linked inspection within the supplied subset. Prohibited inference: original annotation correctness, example equivalence, general component suitability, measured learning or community endorsement.

## Three data conditions
1. **Current:** two VA-Blueprint JSONs, 27 granular components, 40 FeedsInto links. System-prefixed IDs avoid cross-system collisions. Original non-consecutive IDs are preserved. Description, input, output and citation are source records; stages and categories remain explicit. The repository README states MIT but the inspected tree has no standalone LICENSE. Preserve the statement and attribution; clarify the licensing record before broad redistribution. Original paper text and images are not republished as a corpus.
2. **Complementary public data:** six unchanged Vega-Lite example specs at pinned commit 831e308cf9feba791db0c279dea5f7983ca98445. Fields used are filename, description, JSON spec and source URL. The explicit proposed many-to-many mapping links eight components using matching technique semantics. Two line/time-series nodes and two scatter nodes share corresponding examples. Only eight nodes have examples; the other nineteen are null/unmatched. The upstream BSD-3-Clause notice is retained in data/examples/LICENSE. External dataset URLs inside specs are not fetched or used for empirical claims. Gallery availability does not guarantee an example will execute forever.
3. **No suitable open data available in this work:** real novice task phrasing, comprehension difficulties and classroom judgments for this exact extension. No local participant data were collected. The AI-authored query set is interface/retrieval testing data only. Future authorized sessions must document consent, proxy population, aggregate outcomes, access and retention; collect no names or sensitive data. Do not post confidential peer records publicly.

## Provenance and transformation
`data/manifest.json` records original file SHA-256 hashes and pinned revisions. `prepare_data.py` reconstructs source downloads, example records and catalog. Inputs/outputs/citations are not rewritten. Link type in the derived edge record is inferred from the source stage; the display intentionally uses one line style and makes no source-grounded distinction between edge types. Layout is categorical and not geographic, temporal or a physical architecture.

MiniLM text is source name/stage/category/description/inputs/outputs with example filename and description appended in the additional-data condition. Masked mean pooling and normalization produce 384-dimensional vectors. Citation annotations are displayed but not used as independent verified evidence. The app returns candidates above a fixed 0.30 cosine cutoff; low scores and empty matches are not evidence of no suitable component. BM25 uses k1=1.5, b=0.75 and a fixed English stop list. No labels are used for model fitting.

## FAIR and stewardship
Findable: source titles, filenames, commit links, DOI and manifest. Accessible: local snapshot, code and reproducible server, with course public deployment still pending. Interoperable: UTF-8 JSON and explicit IDs; no guessed cross-dataset airport join. Reusable: attribution, licenses, definitions, known limits and recorded transforms; unresolved upstream standalone license noted. Archive source versions. Replace only after reviewing source/mapping changes; never silently refresh the model or corpus.

CARE is not operationalized as an Indigenous-data protocol here because this prototype contains software descriptions rather than Indigenous/community-owned records. The earlier cultural-memory idea would require consulting appropriate cultural authority before collecting or representing such knowledge. No community authority is claimed for the present dataset.
